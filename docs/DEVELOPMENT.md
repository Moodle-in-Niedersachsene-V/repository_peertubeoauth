# Development notes

## Building the AMD module

The repository contains `amd/src/embed_links.js` only. The minified
build in `amd/build/` is generated by Moodle's own Grunt pipeline and is
therefore not committed by hand:

```
npx grunt amd --root=public/repository/peertubeoauth
```

Run this from a Moodle checkout on the build workbench. Hand minified
files never match the output of Moodle's Rollup pipeline and will fail
the Grunt step of the CI run.

## Pitfalls worth knowing

- `instance_config_form()` must be declared `static`. The parent method
  is static and a non static override raises a fatal error at class load
  time, which is silent when `display_errors` is off.
- Configuration is read with `get_config('peertubeoauth', ...)`, using
  the short plugin name without the `repository_` prefix.
- Type level and instance level setting names must not collide, which is
  why the account fields keep their historical `fallback` prefix.
- The OAuth2 POST body must be an encoded string built with
  `PHP_QUERY_RFC1738`. Passing an array makes cURL switch to multipart
  encoding, which PeerTube rejects with `invalid_client`.
- PeerTube channel names allow letters, digits, underscores and dots.
  Hyphens are not permitted.
- The checkboxes for course and user instances are rendered
  automatically from `get_type_option_names()` and must not be added in
  `type_config_form()` again.

## Release checklist

1. Increment `$plugin->version` in `version.php` using the `YYYYMMDDNN`
   scheme, and adjust `$plugin->release` when appropriate.
2. Run `phpcbf --standard=moodle .` followed by `phpcs --standard=moodle .`.
3. Rebuild the AMD module on the build workbench.
4. Run the Semgrep ruleset and review the findings.
5. Push the tag and attach the installable ZIP as a release asset. The
   ZIP root folder must be named `peertubeoauth`.
